# Учёт колориста

PWA без сборки: `index.html` + `css/app.css` + `js/*.js` (классические скрипты, общий глобальный scope).
Документация — [docs/README.md](docs/README.md), процесс разработки — [docs/development.md](docs/development.md),
схема данных — [docs/data-model.md](docs/data-model.md), бэклог — [docs/issues.md](docs/issues.md),
карта функций — [docs/roadmap.md](docs/roadmap.md). Деловые заметки — `private/business.md` (вне git, не публиковать).

## Ветки и выкладка
- `main` = прод: GitHub Pages публикует его мастерице на телефон. Push в `main` — только по явному «да»
  пользователя. Работа идёт в `dev`.
- Выпуск: поднять `APP_BUILD` (store.js); новый файл → `ASSETS` в sw.js и поднять `CACHE`.

## Правила кода
- Код разбит на цеха (`js/<цех>.js`), порядок подключения в index.html: core → costing → store →
  parser → экраны → sync → app. `app.js` — последним (там запуск).
- Поля данных и доменные функции — по-русски (`остаток_г`, `нормыУслуги`). Новый код — в том же стиле,
  комментарии на русском, объясняют «почему».
- Пользовательский текст в HTML — только через `esc()`. После мутации `DB` — `save()`.
- Новые поля базы — через идемпотентный шаг в `мигрируй()` (store.js); данные с сервера и из файла
  тоже идут через неё. Ключ `colorist_v7` не менять — на нём живые данные.
- Цвета — только через переменные палитры в `:root` (css/app.css).
- `data/` — реальные данные клиентов, `server/onecommand.txt` — доступ к серверу: в git не кладём.
  Репозиторий публичный — в тесты только выдуманные данные.

## Проверка
- `node --test` — автотесты логики (tests/). Перед каждым коммитом в логику.
- Браузер: `python -m http.server 8793` → `http://127.0.0.1:8793/`, данные: ⚙️ → «Восстановить из копии» →
  `data/backups/…json`. Порт 8765 на этой машине занят другим проектом.
- `archive/index-monolith-2026-10-30.html` — эталон до разбиения для сверки поведения.
