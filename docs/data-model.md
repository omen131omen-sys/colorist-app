# Модель данных

Вся база — один JSON-объект `DB`. Хранится в `localStorage['colorist_v7']`, на сервере —
в обёртке `{updatedAt, db}`, в файле копии — как есть плюс `_экспорт` (дата) и `_приложение:'colorist-app'`.

```js
DB = {
  materials: [Материал],
  pieces:    [Штучный],      // легаси, UI создания недоступен
  services:  [Услуга],
  works:     [Работа],
  purchases: [],             // легаси, перенесено в expenses
  expenses:  [Трата],
  equipment: [Оборудование],
  нормы:     [Норма],
  _v: 4,
  _updatedAt: 1790187357863, // ms, ставится в save(); по нему решается конфликт синхронизации
  _нормы1: 1,                // флаг миграции: нормы разложены по услугам
  _нормыРаботы1: 1           // флаг миграции: нормы проставлены сентябрьским работам
}
```

id генерируются `uid(префикс)` = префикс + 6 случайных символов: `m…` материал, `s…` услуга,
`w…` работа, `e…` трата, `q…` оборудование, `n…` норма, `p…` штучный.
Старые записи могут иметь короткие id (`m1`, `sv1`, `q1`, `nsh`).

## Материал `materials[]`

| Поле | Тип | Смысл |
|---|---|---|
| `id` | str | |
| `бренд` | str | `'—'` если не указан |
| `название` | str | «Краска Lumia 6.2», «Оксид 6% · Londa». Из него парсятся **код оттенка** (`6.2`) и **процент** (`6%`) |
| `тип` | `краска`/`оксид`/`пудра`/`смывка`/`уход` | см. `TYPE` в core.js |
| `объём_мл` | num | по этикетке, справочно |
| `нетто_г` | num | граммов в упаковке (≈ мл × плотность из `DENSITY`) |
| `тара_г` | num | вес пустой тары, для сверки на весах |
| `цена_упаковки` | num ₽ | обновляется автоматически при приходе с другой ценой |
| `остаток_г` | num | текущий остаток, округление до 0.1 |
| `мин_остаток_г` | num | порог «Мало»; ≤1.5× — «Заканчивается» |

## Услуга `services[]`

| Поле | Смысл |
|---|---|
| `id`, `название` | |
| `иконка` | ключ из `SVC_ICONS` (капля, искра, кисть, ножницы, лист, флакон, расческа, фен) |
| `цена_от`, `цена_до` | вилка; `цена_до = 0` → фиксированная цена |
| `время_мин`, `время_до` | вилка времени, минуты |
| `заметка` | |
| `нормы` | `[{id: норма_id, кол}]` — типовой расход |
| `без_общих` | `true` → не добавлять нормы с флагом `всем` (у «Модели» своя сумма) |

Легаси-поля `цена`, `формула` удаляются миграцией.

## Работа `works[]`

| Поле | Смысл |
|---|---|
| `id`, `дата` (`YYYY-MM-DD`, локальная) | |
| `услуга_id`, `услуга_назв` | название копируется, чтобы пережить удаление/переименование услуги |
| `шаги` | `[Шаг]` — строки расхода материалов |
| `штучные` | `[{id, название, кол_во, цена_за_штуку, списано}]` — легаси |
| `нормы` | `[СнимокНормы]` — копия норм с ценами на момент работы |
| `остаток_смеси_г` | смесь в отход (для блока «Внимание» в отчёте) |
| `время` | минуты, для «доход в час» |
| `цена` | сколько взяли с клиента |
| `формула` | исходный текст из DIKIDI |
| `без_склада` | работа «задним числом» — склад не списывался и не возвращается |
| `себестоимость`, `маржа` | вычислены при сохранении (`calcCost`) и **хранятся** |

**Шаг**: `{название, материал_id, факт_граммы, оксид_id: null, факт_оксида: 0, списано}`.
`списано` — сколько реально ушло со склада (при нехватке меньше `факт_граммы`, остаток упёрся в 0).
У старых записей поля нет → `спис(s)` берёт `факт_граммы`. `оксид_id/факт_оксида` — легаси от
старого формата «краска + оксид в одном шаге»; сейчас оксид — отдельная строка.

**СнимокНормы**: `{норма_id, название, ед, кол, цена, накидка}`.

## Трата `expenses[]`

| Поле | Смысл |
|---|---|
| `id`, `дата`, `сумма`, `заметка` | |
| `категория` | ключ `EXP_CATS`: материалы, расходники, косметика, мелочь, еда, такси, аренда, кредит, налог, реклама, обучение, прочее |
| `материал_id` | есть у закупок со склада — такие записи не редактируются, только удаляются |
| `граммы` | сколько пришло на склад — для отката при удалении |
| `цена_до`, `цена_после` | цена упаковки до/после прихода — для отката цены |

Категория `материалы` вручную не выбирается — только через Приход.

## Оборудование `equipment[]`

`{id, название, кол_во, цена (за шт), дата}` — учёт вложений, в прибыль не входит.

## Норма `нормы[]`

| Поле | Смысл |
|---|---|
| `id`, `название`, `заметка` | |
| `ед` | `г` / `шт` / `раб` (фиксированная сумма за работу) |
| `цена` | ₽ за единицу (для `раб` — за работу) |
| `накидка` | % погрешности поверх строки |
| `всем` | идёт во все услуги автоматически (кол = 1) |

По умолчанию (`нормыПоУмолчанию`): Шампунь 1.63 ₽/г, Маска 4.37 ₽/г, Кондиционер 1.27 ₽/г,
Мелочь 161 ₽ +10% (во все), Расход на модель 300 ₽.

## Миграции (`мигрируй()` в store.js)

Идемпотентны, запускаются при старте, после загрузки с сервера и из файла:

1. Нет `purchases`/`expenses`/`equipment`/`нормы` → создать (expenses строится из purchases).
2. `_нормы1`: разложить типовой расход по услугам по названию (`ТИПОВОЙ_РАСХОД`).
3. `_нормыРаботы1`: сентябрьским работам без норм проставить снимок и пересчитать маржу.
4. Оксидам дописать бренд в название («Оксид 6% · Londa»).
5. Траты «прочее» с заметкой «еда/обед/перекус» → категория `еда`.
6. Услуги: `цена` → `цена_от/цена_до`, удалить `цена`, `формула`.

Новая миграция — добавить шаг в конец `мигрируй()`, сделать его идемпотентным
(флаг `_имяN` или проверка состояния).

## Прочие ключи localStorage

| Ключ | Смысл |
|---|---|
| `colorist_sync` | `{url, key}` подключённого сервера |
| `colorist_sync_at` | время последней успешной синхронизации |
| `colorist_backup_at` | время последней копии (файлом или через сервер) |
