# Как вести разработку

## Ветки

| Ветка | Что это | Куда попадает |
|---|---|---|
| `main` | **то, что стоит у мастерицы на телефоне** | GitHub Pages публикует её на https://omen131omen-sys.github.io/colorist-app/ через 1–2 минуты после push |
| `dev` | текущая работа | никуда, только хранится на GitHub |

Правило: в `main` — только проверенные выпуски. Всё остальное делается в `dev`
(или в отдельной ветке под большую задачу, которая потом вливается в `dev`).

## Выпуск новой версии

1. В `dev`: все тесты зелёные (`node --test`), приложение проверено в браузере на реальной копии.
2. Поднять `APP_BUILD` в [js/store.js](../js/store.js) (`'ГГГГ-ММ-ДД · N'`, N — сквозной номер).
3. Если добавлялись файлы — вписать в `ASSETS` в [sw.js](../sw.js) и поднять `CACHE`.
4. Перед выпуском, который трогает данные или синхронизацию, — мастерица делает копию:
   ⚙️ → «📲 Отправить копию» → «Избранное» Telegram.
5. Влить и выложить:
   ```
   git checkout main
   git merge --ff-only dev
   git push origin main
   git checkout dev
   ```
6. Через пару минут открыть приложение → ⚙️ → проверить номер сборки и «синх. только что ✓».

**Откат**, если что-то сломалось: `git revert <коммит>` в `main` и push — старая версия вернётся
через пару минут. Данные на телефонах при этом не трогаются: они лежат в браузере, а не на сайте.

## Тесты

```
node --test
```

Ничего устанавливать не нужно (Node.js 18+, на этой машине 24). Тесты в [tests/](../tests/)
грузят файлы цехов в Node без браузера ([tests/helpers.js](../tests/helpers.js)) и проверяют чистую логику:

| Файл | Что проверяет |
|---|---|
| `parser.test.js` | распознавание формул DIKIDI и списков покупок |
| `costing.test.js` | цена за грамм, нормы, себестоимость, светофор маржи |
| `store.test.js` | миграции старых форматов, сортировка склада |
| `sync-merge.test.js` | слияние баз с двух устройств |

Данные в тестах выдуманные (`MATERIALS` в helpers.js) — репозиторий публичный, реальных данных туда
не кладём. Нашли строку из DIKIDI, которая разбирается неправильно, — сначала добавьте её в
`parser.test.js` с ожидаемым результатом, потом чините парсер.

## Проверка в браузере

```
python -m http.server 8793
```

→ http://127.0.0.1:8793/ → ⚙️ → «Восстановить из копии» → файл из `data/backups/`.
Service worker на http не регистрируется — это нормально. Порт 8765 на этой машине занят другим проектом.

## Что не попадает в git

`.gitignore`: `data/` (копии с данными клиентов, Excel), `archive/` (монолит до разбиения, он есть
в истории), `server/onecommand.txt` (IP сервера и путь к ssh-ключу).
