# Найденные проблемы и идеи улучшений

Составлено при полном разборе кода 2026-10-30. Пометки: 🔴 портит данные · 🟠 риск/неудобство ·
🟡 косметика/техдолг · 💡 идея. «Проверено» — воспроизведено в браузере на реальной копии.

## 🔴 Баги, которые портят данные

### 1. Правка работы, у которой удалена услуга, теряет работу и рисует граммы на складе — проверено
[js/works.js](../js/works.js) `saveWork()`: блок правки сначала возвращает граммы на склад и
выкидывает старую работу из `DB.works`, а потом падает на `s.id` (услуга не найдена).
`save()` не вызван, но изменения остались в памяти — следующее любое сохранение запишет их:
работа пропала, остаток завышен.
**Исправление:** в `saveWork()` проверять `s` до любых мутаций; в мастере при отсутствии услуги
предлагать выбрать другую (в `<select>` сейчас молча показывается первая).

### 2. Синхронизация «побеждает последний» по всей базе
[js/sync.js](../js/sync.js): сравнивается только `updatedAt` всей базы. Сценарий: на планшете
устаревшие данные, его открыли без сети и поправили одну цифру → `_updatedAt` новее → при появлении
сети планшет **целиком перезаписывает** сервер, а с ним работы, внесённые с телефона.
Ещё: время берётся с часов устройства — расхождение часов решает, чьи данные выживут.
**Варианты (по возрастанию сложности):**
- перед push сверять, не изменился ли сервер с момента последнего pull (`If-Match`/ревизия) и при
  конфликте сначала подтягивать;
- слияние по записям: у каждой записи `_updatedAt`, сливать массивы по `id`, удаления — «надгробиями»;
- хранить на сервере историю версий (откат при ошибке).

### 3. Service worker кэширует ответы сервера синхронизации
[sw.js](../sw.js) перехватывает **все** GET, включая `GET {sync}/data` на другой домен: полная база
оседает в Cache Storage, а без сети на `/data` отдаётся кэш или вообще `index.html`
(→ «ошибка: Unexpected token <»). **Исправление:** в fetch-обработчике пропускать запросы не к своему
origin (`if (new URL(e.request.url).origin !== location.origin) return;`).

## 🟠 Риски

4. **Исходника сервера нет в проекте** — только установщик nginx. Забрать с сервера код
   `colorist-sync` и unit-файл в `server/sync/` ([workshops/server.md](workshops/server.md)).
5. **Нет git.** Сейчас откат — только `archive/`. Завести репозиторий, `data/` и `server/onecommand.txt`
   — в `.gitignore` (там данные и доступы).
6. **Данные клиентов рядом с сайтом.** Если хостинг раздаёт всю папку, `data/backups/*.json` доступны
   по ссылке. Выкладывать только файлы приложения (чек-лист в [README.md](README.md)).
7. **Одна база на сервер, один ключ.** Для «многим понравилось» каждой мастерице нужен свой сервер.
   Для раздачи другим колористам нужны аккаунты: один сервис, отдельная база на пользователя.
8. **Нет автотестов.** Самые ценные для тестов — чистые функции: `parser.js` (реальные строки DIKIDI
   → ожидаемый материал), `calcCost`, `sortMats`, миграции. Проверку можно запускать в Node без браузера.

## 🟡 Техдолг и косметика

9. **Остатки старой фиолетовой палитры:** `manifest.json` `theme_color: #7c3aed` (в index.html
   `#a9857b`), шапка `rgba(244,244,247,.86)` (серая, а фон тёплый `#f5f0ec`), рамки `#e0d6ff`
   у блоков формулы, фон прогресс-бара `#edecf2`, `.seg` `#ececf1`, `.badge.n`.
10. **Штучные расходники (`pieces`)** — в интерфейсе недостижимы, но код живёт в stock/works/report
    (`matKind('p')`, `pieceSheet`, `addNwPiece` и др.). Решить: вернуть (перчатки, фольга в штуках)
    или удалить.
11. **Мёртвый код:** `LEN/DEN/LEN_K/DEN_K`, `blankMatrix`, `deepc`, `TYPE_BADGE`, `backupStale`,
    `addNwPiece`, `purchases`, поля `оксид_id/факт_оксида` (в реальных данных не встречаются).
12. **Тексты «тестовые данные»** в «Опасной зоне» — демо-данных больше нет, кнопка просто очищает
    базу. Переименовать в «Очистить все данные».
13. `renderServices`: при отсутствии времени выводится «0 мин» (условие перевёрнуто).
14. `doRestockMat` прибавляет граммы без округления (`doIncoming` округляет) — копятся хвосты 0.0000001.
15. При правке работы со старыми шагами «краска + оксид» оксид терялся бы (сейчас таких данных нет).
16. `MARG_FROM` захардкожен — для новых пользователей не нужен (у них маржа честная с первого дня).
    Сделать настройкой или выключать, если в базе нет работ до этой даты.
17. Инлайновые `onclick="…"` в строках — работают, но любое имя функции глобально. При росте —
    перейти на делегирование событий (`data-action`) по цехам.

## 💡 Идеи развития (из устройства продукта)

- **Клиенты:** карточка клиента с историей формул — повторное окрашивание в один тап
  (сейчас формула живёт только в работе).
- **Импорт из DIKIDI** напрямую (API/экспорт) вместо копирования формулы.
- **Подсказка цены:** по себестоимости и целевой марже предлагать цену («чтобы выйти на 60% — от 3 200 ₽»).
- **Прогноз заказа:** средний расход каждого оттенка в неделю → «закончится через ~10 дней».
- **Инвентаризация:** режим взвешивания тюбиков с учётом `тара_г` (поле уже есть).
- **План/цель месяца** в Отчёте, сравнение с прошлым месяцем.
- **Экспорт отчёта** (CSV/PDF) для налоговой и самозанятости.
- **Фото до/после** — но не в localStorage (лимит ~5 МБ): нужен IndexedDB или сервер.
