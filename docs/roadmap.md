# Дорожная карта

Как читать: этапы идут по порядку зависимостей, но браться за этап стоит **только когда сработал его
триггер** — до этого он просто описан, чтобы не придумывать заново. У каждого этапа: зачем, когда
начинать, что входит, когда готово, от чего зависит. Статусы: ✅ сделано · 🔄 в работе · ⏸ ждёт
триггера · 💭 идея, не решено.

Деловая сторона (модель заработка, цены, переговоры) — в `private/business.md`, вне git.

---

## Этап 0 — Фундамент 🔄

**Зачем:** чтобы развивать проект, не боясь сломать то, чем мастер пользуется каждый день.

| Что | Статус |
|---|---|
| Монолит разбит на цеха, документация по каждому | ✅ |
| Git, ветки `main` (прод) / `dev` (работа), процесс выпуска — [development.md](development.md) | ✅ |
| Автотесты логики (`node --test`) | ✅ |
| Исправлены 3 бага: правка работы без услуги, слияние при синхронизации, кэш SW | ✅ в `main`, не выложено |
| Код сервера в проекте, найдены серверные копии за 30 дней | ✅ |
| **Выкладка** исправлений мастеру | ⏸ ждёт её резервной копии |

**Готово, когда:** у мастера стоит сборка с исправлениями, синхронизация показывает «синх. только что ✓».

## Этап 1 — Сильный продукт для одного мастера ⏸

**Зачем:** то, ради чего приложение будут хотеть другие. Пока делаем для одного мастера, но всё,
что делаем, должно переехать в многопользовательскую версию без переделки.
**Начинать:** после этапа 0.

| Что | Статус | Заметки |
|---|---|---|
| **Клиентки с историей формул** | 💭 | Формула вводится один раз, карточка клиентки показывает визиты, формулы, заметки «как получилось». Снимает двойной ввод в DIKIDI. Старт без телефона (персональные данные). В синхронизацию добавить список `clients` |
| **Формула голосом** | 💭 проверить | Сначала отдельная тестовая страница на её телефоне: понимает ли речь («восемь два», «полтора процента»), удобно ли в перчатках. Зависит от iPhone/Android |
| Палитра склада по бренду | 💭 | Только по каждой линейке отдельно, номера строго по бренду. Идеально — с официальным каталогом бренда (см. этап 3) |
| Режим смешивания (накопительные граммы для весов) | 💭 проверить | Не факт, что удобно — только через тест |
| Масштаб формулы под нужный объём смеси | 💭 | Интересно, но польза неясна |
| Мелочи из [issues.md](issues.md) (№14–18) | ⏸ | Попутно |

**Готово, когда:** мастер ведёт клиенток и формулы только в приложении, DIKIDI — только для записи.

## Этап 2 — Несколько мастеров на одном сервере ⏸

**Зачем:** подключить первых платящих мастеров **на текущей версии**, проверить спрос до большой разработки.
**Начинать:** когда есть 2–3 мастера, готовых платить.

| Что | Заметки |
|---|---|
| Сервер: у каждого ключа свой файл базы | Небольшая правка [server/sync/server.js](../server/sync/server.js); приложение не меняется |
| Ежедневные копии — по каждому мастеру | Сейчас общие |
| Учёт мастеров для себя | Хотя бы список: кто, ключ, оплачено до |
| Порядок подключения | Ключ → ссылка → «Восстановить из копии» / перенос склада из Excel |
| FAQ / видеоинструкции | Поддержку первой линии ведёт не разработчик |

**Готово, когда:** 3 мастера работают каждый со своей базой, данные не пересекаются.

---

## Этап 3 — Бренд и надстройки под клиента ⏸

**Зачем:** брать больше за индивидуальное, **не плодя копии программы.**
**Начинать:** первый заказ на брендирование/свою фишку или партнёрство с брендом краски.

| Что | Заметки |
|---|---|
| Настройки клиента: название, логотип, цвета, иконка | Цвета уже в переменных `:root` — бренд = настройки, не переделка |
| Включаемые функции (флаги) на клиента | Своя фишка → в общий код под флагом; удачная → включить всем |
| Каталоги брендов краски | Линейки, номера, фасовки, цены; основа для палитры и точного распознавания |

**Правило:** одна программа на всех. Никаких форков под клиента.

**Готово, когда:** новый брендированный клиент заводится настройкой, без правок кода.

## Этап 4 — Серверная версия (v2) ⏸

**Зачем:** без неё невозможны запись клиентов, студии и масштаб больше десятка мастеров.
**Начинать:** >10 мастеров, или первая студия, или партнёр, раздающий приложение своей сети.

| Что | Заметки |
|---|---|
| Сервер в России | Персональные данные клиентов (152-ФЗ). Текущий — в зарубежном облаке |
| Вход для мастера (аккаунт), админка для владельца сервиса | Создать / приостановить мастера |
| Хранение по записям, сервер — источник истины | Вместо одного JSON на базу; слияние из этапа 0 становится не нужно |
| Мониторинг и копии | Узнать о падении раньше мастера |
| Миграция действующих мастеров | Без потери данных; через тот же формат копии |

**Готово, когда:** мастер входит с любого устройства по логину, данные живут на сервере в России.

## Этап 5 — Запись клиентов ⏸

**Зачем:** отказаться от DIKIDI, замкнуть цепочку «запись → работа → история клиентки».
**Зависит от:** этапа 4 (расписание должно жить на сервере), этапа 1 (клиентки).
**Перед стартом выяснить:** что именно не работает в DIKIDI; приходят ли клиенты через его каталог.

| Шаг | Что |
|---|---|
| 5.1 Заявки | Страница: услуга из прайса + удобное время → заявка мастеру в Telegram, подтверждение вручную. DIKIDI остаётся |
| 5.2 Календарь | Вкладка «Записи», из записи одним касанием — работа |
| 5.3 Онлайн-запись | Расписание, свободные окна по длительности услуги, защита от накладок, напоминания, перенос/отмена |

Заявки клиенток хранятся **отдельно** от базы мастера — посторонний не должен дотянуться до склада и денег.

---

## Этап 6 — Студия ⏸

**Зачем:** несколько мастеров под одним владельцем.
**Зависит от:** этапа 4.

Роли (владелец / администратор / мастер), общий склад, **чек по мастерам** (кто что делал, время,
материал), сравнение мастеров. Позиционирование: прозрачность, а не «приложение спасёт от перерасхода».

---

## Этап 7 — Партнёрства с брендами и поставщиками 💭

Заказ дистрибьютору из списка «Заказать», каталоги брендов, обезличенная статистика расхода
(только агрегаты и с согласия мастеров). Подробности и принципы переговоров — `private/business.md`.

## Открытые вопросы (к мастеру)

- Какой телефон — iPhone или Android? (голос, уведомления)
- Что именно «не работает» в DIKIDI? Приходят ли клиенты через его каталог?
- Что раздражает в процессе работы с клиенткой — от кресла до ухода?
- Были ли работы после 26 октября? (на сервере последние данные от 26-го — проверить синхронизацию)
- Кому понравилось приложение — мастерам-одиночкам или владелицам студий?
