# Цех «Распознавание» — [js/parser.js](../../js/parser.js)

Превращает свободный текст в строки с материалами. Используется в мастере работы (формула из
DIKIDI) и в «Приходе списком» (накладная, сообщение поставщику).

## `matchMaterial(norm, mats, used)` — общий подбор материала по строке

Возвращает `{id, кандидаты}`: однозначно найден → `id`; несколько → `кандидаты` (≤ `MAX_CAND = 8`);
иначе оба `null`.

1. **По типу:**
   - есть `N%` → оксиды с тем же процентом (`_matPct`);
   - слова пудр/блонд/обесцв/порош/осветл → пудры;
   - бонд/плекс/защит/уход/шампун/кондицион → уход;
   - иначе код оттенка `N.NN` → краски с **точно** тем же кодом (`9.2 ≠ 9.23`, `_matCode`; `6,2` = `6.2`).
2. Ничего по типу → поиск по словам (от 3 букв + алиасы).
3. Несколько кандидатов → сужение по словам-подсказкам: побеждают материалы с наибольшим числом
   совпадений в «название + бренд». Алиасы `_ALIAS`: вв/бб→bb, люмиа→lumia, лонда→londa, эстель→estel…
4. Всё ещё несколько → «голые» цифры строки (кроме уже разобранных граммов/процентов/суммы) должны
   встречаться в названии («шаг 1» / «шаг 2»).
5. > 8 кандидатов → считаем «не распознано» (родовое слово цепляет полсклада).

## `parseFormulaText(text, mats)` — формула
Разделители: `+`, перевод строки, `;`. Граммы: `20гр`, `20 г`, `20g`, `20мл`, иначе число в конце.
Строка сохраняется, если есть граммы или материал.
Пример: `10.2 (20гр) + 9.23 (5гр) + 1,5% (60гр)`.

## `parseIncomingText(text, mats)` — список покупок
Строка = позиция. Сумма: `620 ₽` / `620 руб` / `— 620` в конце / последнее число ≥ 3 знаков.
Упаковки: `2 шт`, `2 уп`, `х2`/`x2`/`×2`.
Пример: `Lumia 6.2 — 2 шт — 1240`.

## `incFill(r)` — достраивание строки прихода из карточки материала
Нет упаковок, но есть сумма → `сумма / цена_упаковки`, если почти целое (±0.12), иначе 1.
Дальше граммы = уп × нетто, сумма = уп × цена. Читает `DB` через `mById` — единственная нечистая функция.

## Как улучшать
Функции чистые — идеальное место для автотестов: набор реальных строк из DIKIDI → ожидаемые id.
