# Цех «Синхронизация и копии» — [js/sync.js](../../js/sync.js)

## Протокол с сервером

| Запрос | Ответ |
|---|---|
| `GET {url}/data`, заголовок `X-Key` | `200 {updatedAt, db}` / `404` — пусто / `401` — неверный ключ |
| `PUT {url}/data`, `X-Key`, тело `{updatedAt, db}` | `2xx` |
| `GET {url}/health` | `ok` (проверка установщика) |

Сервер хранит **один документ на всю базу** — без пользователей и истории (по клиентскому коду;
исходника сервера в проекте нет, см. [server.md](server.md)).

## Логика обмена (с 2026-10-30)

Каждое устройство хранит **общую точку** — `colorist_sync_base`: базу ровно в том виде, в каком она
последний раз совпала с сервером. Обмен (`pushSync()` = `pullSync()`, строго по одному за раз):

1. `GET /data`.
2. Кто менялся с общей точки: **мы** — `DB._updatedAt ≠ base._updatedAt`; **они** —
   `remote.updatedAt ≠ base._updatedAt`. Сравнение на равенство, а не «кто новее», поэтому часы
   устройств ни на что не влияют.
3. | мы | они | действие |
   |---|---|---|
   | — | — | ничего, отметить «синхронизировано» |
   | ✓ | — | PUT своей базы |
   | — | ✓ | взять базу сервера целиком (+ `мигрируй()`) |
   | ✓ | ✓ | `слитьБазы(base, DB, remote)` → PUT, тост «Объединено…» |
4. Успешный обмен → `markSynced(json)`: новая общая точка, `colorist_sync_at`, `colorist_backup_at`.

### Слияние `слитьБазы` / `слитьСписок` / `слитьЗапись`
- Списки (`SYNC_LISTS`) — по `id`. Новые записи с обеих сторон остаются. Удалённая с одной стороны
  запись удаляется, если другая её не правила; если правила — правка важнее, запись остаётся.
- Запись, изменённая с обеих сторон, — поле за полем: поменялось с одной стороны — берём его,
  с обеих — наше. **Остатки** (`остаток_г`, `остаток_шт`) складываются по разнице:
  `base + (наше − base) + (их − base)`, не ниже 0 — списание на телефоне и приход на планшете учтутся оба.
- Нет общей точки (первый обмен после обновления приложения) — объединение, при расхождении одной
  записи побеждает база с более свежим `_updatedAt`.

### Осознанная замена
Восстановление из копии и «Сбросить» вызывают `syncReplaceNext()` → флаг `colorist_sync_force`:
следующий обмен заливает базу как есть, без слияния. Ставится только при подключённом сервере.

### Прочее
- `scheduleSync()` — дебаунс 2 с после каждого `save()`; `online` → обмен; при старте — обмен.
- `connectSync()` — нормализует адрес (`https://`, без хвостового `/`), сбрасывает общую точку;
  если на сервере есть данные, **они заменяют локальные**; 404 → заливает своё.
- `disconnectSync()` — забывает адрес, общую точку и флаг замены.
- `syncStatusText()` — статус, в т.ч. предупреждение о http-адресе со страницы https.

Ограничение: между GET и PUT другое устройство теоретически может успеть записать своё — окно
в доли секунды. Закрыть полностью можно только на сервере (ревизия + `If-Match`).

## Резервные копии
- `backupBlob()` — `{...DB, _экспорт, _приложение:'colorist-app'}`, имя `учёт-колорист-YYYY-MM-DD.json`.
- `shareBackup()` — системное «Поделиться» (на телефоне → Telegram «Избранное»), иначе скачивание.
- `downloadBackup()`, `importBackup(input)` — проверка формата, подтверждение, `мигрируй()`, `save()`
  (а значит и push на сервер).
- `backupInfoText()` — сколько дней назад копия. `backupStale()` — **не используется**.
